# 실시간 날씨·미세먼지 글로벌 대시보드 (`26-w10-weather`)

> 전 세계 실시간 기상 관측 및 미세먼지 데이터를 제공하는 Open-Meteo API 연동 React 대시보드입니다.  
> Google Antigravity IDE의 계획 기반(Plan-driven) 에이전트 워크플로우를 활용하여 제작되었습니다.

---

## 🌟 1. 소개

본 프로젝트는 전 세계 주요 도시 및 사용자가 검색한 도시의 **실시간 기상 상태, 24시간 시간별 기온 변화, 7일간 주간 예보, 실시간 미세먼지(대기질)** 정보를 한눈에 파악할 수 있는 모던 카드형 반응형 대시보드입니다.

### 🎯 핵심 기능
- **주요 도시 빠른 선택**: 서울(강서), 서울(시청), 인천, 부산, 대구, 대전, 광주, 제주 등 프리셋 원클릭 조회
- **실시간 현재 날씨**: 기온, 체감 온도, 습도, 풍속, 강수량 및 한국어 날씨 라벨과 Lucide 동적 아이콘
- **환경부 기준 미세먼지 진단**: PM10, PM2.5 측정치 및 4단계(좋음/보통/나쁨/매우 나쁨) 컬러 뱃지
- **24시간 시간별 기온 SVG 차트**: 오늘 하루 시간대별 기온 변화를 나타내는 미니 꺾은선 차트 및 시간별 날씨 아이콘
- **7일간 주간 예보**: 향후 7일간의 요일별 날씨, 강수 확률(%), 상대적 최고/최저 기온 범위 바 시각화
- **글로벌 도시 검색 (Debounce 적용)**: 400ms 디바운스가 적용된 영문 도시(Seoul, Tokyo, Paris, New York 등) 자동완성 검색

## 🤖 2. 어떻게 만들었나요 (Antigravity IDE 경험)

1. **GitHub Copilot(인라인 완성)과의 차이점**:
   - 기존의 Copilot은 개발자가 코드를 치는 순간순간 단어나 라인을 추천해 주는 수동적 어시스턴트에 가까웠다면, **Antigravity IDE는 전체 프로젝트의 파일 구조와 규칙(`GEMINI.md`)을 스스로 파악하고 큰 단위의 작업을 자율적으로 수행하는 독립적인 코딩 에이전트**였습니다.
2. **구현 계획(Implementation Plan) 중심의 개발**:
   - 무작정 코드를 수정하거나 덮어쓰지 않고, 작업을 시작하기 전 **구현 계획(Implementation Plan)** 아티팩트를 먼저 작성하여 작업 범위, 아키텍처 다이어그램, 컴포넌트 분리 전략을 개발자에게 제시하고 승인([Proceed])을 받은 후 진행했습니다. 이 과정 덕분에 코드 충돌이나 불필요한 재작업 없이 안정적인 개발이 가능했습니다.
3. **자체 기능 검증(Walkthrough) 관찰**:
   - 작업 완료 후 `vite build`를 실행하여 린트/번들 에러를 자체 확인하고, 결과 리포트인 **Walkthrough** 문서를 생성하여 어떤 파일이 추가/수정되었고 무엇이 검증되었는지 투명하게 공유해 주는 개발 프로세스가 매우 인상적이었습니다.

## 📡 3. 데이터는 어떻게 가져오나요 (외부 API 아키텍처)

1. **Open-Meteo API의 특징**:
   - 회원가입이나 Secret API Key 발급 절차가 필요 없는 **완전 공개 무료 기상 API(Public API)**입니다.
   - 현재 기상(`forecast`), 24시간/주간 예보(`hourly`, `daily`), 대기질(`air-quality`), 지오코딩(`geocoding`) 엔드포인트를 표준 HTTPS로 제공합니다.
2. **UI 컴포넌트와 API 통신 로직(`src/api/weather.js`)의 분리(Decoupling)**:
   - UI 렌더링 코드(`App.jsx`, 하위 컴포넌트)와 네트워크 호출 로직을 분리함으로써, API 엔드포인트나 파라미터가 변경되더라도 컴포넌트 수정 없이 `weather.js`만 관리할 수 있어 **유지보수성과 가독성**이 크게 향상되었습니다.
3. **도시 검색창에 '디바운스(Debounce)'가 필수적인 이유**:
   - 사용자가 검색창에 "London"을 입력할 때 `L`, `o`, `n`, `d`, `o`, `n` 한 글자를 입력할 때마다 실시간으로 네트워크 요청을 전송하면 짧은 시간에 수십 건의 불필요한 요청이 발생합니다.
   - 이는 서버에 DoS(서비스 거부) 형태의 부하를 유발하며, API 제공자로부터 `429 Too Many Requests(요청 한도 초과)`로 IP 차단을 당할 수 있습니다.
   - 따라서 사용자의 연속 타이핑이 끝난 뒤 **400ms 동안 추가 입력이 없을 때 단 한 번만 API를 호출하도록 디바운스(Debounce)**를 적용하여 네트워크 자원을 효율적으로 보호했습니다.

## 🛡️ 4. 보안에서 확인한 것 (사이버보안과 체크포인트)

1. **Public API vs Private/Secret Key API의 차이점**:
   - **Public API (예: Open-Meteo)**: 읽기 전용 데이터이며 인증 키가 필요 없어 프론트엔드 브라우저에서 직접 `fetch()`를 수행해도 보안상 안전합니다.
   - **Secret Key API (예: 결제 모듈, 고객 개인정보 DB 등)**: 유료 과금이 발생하거나 권한 제어가 필요한 API는 브라우저 코드에 키를 절대 포함해서는 안 됩니다.
2. **프론트엔드 직접 호출 시 보안 사고와 백엔드 프록시(BFF)의 필요성**:
   - 만약 유료 결제 Secret Key나 관리자 권한 토큰을 React 프론트엔드 소스코드에 하드코딩하면, 브라우저의 **개발자 도구(Network 탭, Sources 탭)**나 번들링된 JS 파일에서 누구나 평문으로 키를 탈취할 수 있습니다.
   - 이로 인해 **악의적인 대량 API 호출로 인한 수천만 원의 과금 폭탄**이나 **데이터 유출 사고**가 발생합니다.
   - 따라서 이러한 보안 API는 반드시 서버 사이드(Node.js/Spring 등)에 **BFF(Backend For Frontend) 프록시 서버**를 구축하여, 비밀 키는 서버 환경변수(`ENV`)에 안전하게 숨기고 프론트엔드와는 자체 인증된 세션/토큰으로만 통신해야 합니다.
3. **HTTPS와 Mixed Content (혼합 콘텐츠) 차단 방어**:
   - 현대 웹 브라우저는 `https://` 보안 배포 사이트에서 암호화되지 않은 `http://` API를 호출하려고 할 때 데이터 변조나 도청(MITM 공격)을 방지하기 위해 통신을 강제로 차단(**Mixed Content 차단**)합니다. 본 프로젝트는 모든 API 통신을 안전한 HTTPS 프로토콜로 구성하여 배포 환경에서도 안전하게 동작합니다.

## 🎨 6. 커스터마이징한 부분 (나만의 개성 더하기)

1. **온도 단위 원클릭 변환 토글 (°C ↔ °F)**:
   - 헤더 상단에 섭씨/화씨 토글 스위치를 배치하여, 클릭 한 번으로 현재 기온, 체감 온도, 24시간 기온 차트 수치, 7일 주간 예보 범위까지 일괄 변환되도록 상태를 연동했습니다.
2. **최근 본 도시 저장 및 원클릭 재방문 (localStorage 연동)**:
   - 사용자가 검색하거나 선택한 도시를 브라우저 로컬 스토리지에 자동 저장하고, 상단에 세련된 칩 형태로 최대 5개까지 노출하여 언제든 원클릭으로 다시 볼 수 있으며 개별 삭제(`X`)도 지원합니다.
3. **날씨 및 주야간(is_day) 반응형 동적 비주얼 테마**:
   - 현재 기상 상태(맑음, 비, 눈, 흐림)와 낮/밤 여부에 따라 대시보드 전체 배경의 은은한 그라데이션이 동적으로 전환되는 반응형 테마 CSS를 구현했습니다.
4. **상세 기상 데이터 표시 (자외선 지수, 일출/일몰, 강수 확률)**:
   - 현재 날씨 카드에 실시간 자외선 지수(UV Index 5단계 등급 뱃지), 오늘의 일출 및 일몰 시각, 최대 강수 확률을 서브 메트릭 카드로 추가하여 기상 정보의 깊이를 한층 강화했습니다.
